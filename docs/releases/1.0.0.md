# Falcon OSINT Framework 1.0.0

Released: 2026-11-13

1.0 is a compatibility promise: the catalog, the local workspace, the backup
format and the documented data contracts stay usable for at least one minor
cycle. The release notes below say what is covered and what is not, because a
promise that hides its exceptions is not a promise.

## Highlights

- **Catalog of 182 tools across 9 packs**, every entry with a status, a
  verification date and a health check. `npm run db:provenance` fails the release
  if an entry lacks provenance.
- **Reproducible database build.** `db:validate`, `db:import` and `db:compile`
  are idempotent and covered by tests; an entry removed from JSON disappears from
  the database on the next import, and an empty catalog is refused instead of
  wiping the table.
- **Offline-first workspace.** The SQLite catalog, the WASM engine and the app
  shell are precached; a second load works with the network disabled, and a
  corrupt database shows a recoverable panel that never deletes local data.
- **Local assistant with an explicit boundary.** Retrieval runs offline, model
  calls go to loopback Ollama or OpenRouter with per-query consent and a prompt
  preview, keys live in `sessionStorage`, and the query history records the exact
  context sent.
- **Accessibility and performance evidence.** axe reports 0 violations across 8
  views, and the performance gate measures catalog render, database open, bundle
  size, heap and retrieval over 1,000 documents.
- **Legal and ethical gate G9.** Source terms review, privacy impact assessment,
  lawful-use guidance and a takedown path, with a public correction form.

## Upgrade notes

- From `0.7.0-beta`: no manual migration. Schema version stays at 2, the
  `falcon:*` browser keys are compatible and the database is rebuilt from the
  JSON sources.
- `db:import` now deletes catalog entries that are no longer in the JSON. Entries
  added by hand to a local database must be moved into a pack file before the
  next import.
- A backup from `0.7.0-beta` restores with `format_version` 1 and the same
  `local_data` and `queries` structure.
- The version in the backup envelope changes to `1.0.0`; the format itself does
  not.

## Rollback

1. Check out the previous tag (`v0.7.0-beta`).
2. `npm install && npm run build`.
3. Open Falcon and use the recovery panel's cache reset if the service worker
   still serves 1.0 assets.
4. Restore the backup taken before the upgrade if local data changed in 1.0.

Local data is not downgraded by Falcon: a 1.0 backup restores into 0.7 because
the format did not change, and the SQLite file from 1.0 stays readable under the
same schema version.

## Known limitations

- Assistant and real-model evaluation are deferred to 1.1. The offline retrieval
  suite and the assistant prompt contract still run in the unit suite.
- The scheduled source-health workflow (G2) and the screen-reader pass (G4) remain
  open; the manual a11y checks and the automated axe scan pass.
- G9 documents are delivered but not reviewed by counsel. The project records
  this as an accepted risk for 1.0 instead of claiming legal sign-off.
- API and plugin contracts are present but not frozen as public, versioned
  contracts (G6).
- Release artifacts are not cryptographically signed.
